# Complete saved-dataset audit

This post-hoc supplement closes a specific composition gap: the earlier
[combined policy-attribution checker](../policy-attribution/README.md) verifies
each supplied row, but a valid subset can pass that command. This new entry point
checks the entire retained study against separately saved expected membership,
coverage certificates, and aggregates, while also running the same pinned
dynamics and policy-attribution verifiers.

**No new experiment or improved policy result is claimed.** Frozen scientific
files, the failed P5 prediction, and the 423-versus-417 justified-completion result
remain unchanged. The existing [saved-group checker](../tools/check_saved.py)
already performs many study-level checks. This supplement composes those checks
with policy attribution in one command and adds fixed provenance pins, explicit
duplicate/extra-certificate rejection, strict case identity, path-index checks,
group-metric reconciliation, and adversarial regressions.

## The evidence was published

The earlier review's partial snapshot lacked `cases.json`, group certificates,
and aggregates. Those files are present in the public study at commit
[`68d60a8`](https://github.com/EastonSell/after-the-timeout/commit/68d60a8b4fead07a024b1ecdb00a9875c161b36b).
The group certificates are transported as checked payloads and recovered by the
existing reconstructor. No missing historical artifact was fabricated or
regenerated to create this supplement.

The expected membership comes from `cases.json` and the policy list retained in
`results-v1/run-input.json`, not from the rows being checked. Six expectation
artifacts and both reused verifier source files have fixed SHA-256 pins in
`completeness_check.py`. Their provenance is recorded in `SOURCE.json`. The CLI
refuses edited expected files rather than accepting a self-consistent reduction
of the dataset. These artifacts are independent of the supplied rows as audit
inputs, not an independently designed scientific oracle or timestamped
preregistration.

## Run without simulations

Python 3.10+ and the standard library are sufficient. From the repository root:

```sh
python -B -m unittest discover -s studies/recovery-composition/dataset-completeness -v
python -B -m unittest discover -s studies/recovery-composition/policy-attribution -v
python -B -m unittest discover -s studies/recovery-composition/packaging -v
python -B studies/recovery-composition/tools/reconstruct_payloads.py ../recovery-complete-review
python -B studies/recovery-composition/dataset-completeness/completeness_check.py ../recovery-complete-review
```

Choose a fresh absent reconstruction destination with an existing parent. If a
verified reconstruction already exists, reuse it in the last command. The new
checker reads inputs and prints JSON only; it never creates or overwrites a
report file. For an external copy of this supplement, provide `--study-root`
pointing to the published study that contains `source/checker.py` and
`policy-attribution/policy_replay.py`. Tests in an external copy accept the same
location through `RECOVERY_STUDY_ROOT`.

To audit another serialization, use `--rows PATH` for a JSONL or JSONL.gz file.
The expected artifacts still come from the pinned reconstruction. A passing
alternative file must contain the full accepted membership and match the
retained coverage certificates and aggregates. A subset is not accepted. Group
order and path order within a contiguous group may change; split/repeated groups
are rejected. Blank JSONL rows, duplicate JSON keys and non-finite JSON numbers
are rejected.

No simulator or runner is imported by these commands. The repository's wider
model tests are separate and can run simulator fixtures; they are not part of
this saved-evidence-only verification recipe.

## Checks and retained-data result

On 24 October 2026, the new command accepted the complete retained dataset:

- 800 unique cases, exactly equal to the pinned full case objects.
- 4 registered policies and exactly 3,200 case-policy groups.
- 86,796 unique terminal scheduler paths with complete per-group path indices.
- 233,172 checked scheduler branch nodes.
- 338,660 registered-policy decisions checked after dynamics validation.
- Every group coverage certificate and recomputable metric reconciled.
- All family-policy and global aggregate counts matched, including the retained
  independent recount's coverage-manifest digest:
  `53bbf03853f8252529257ea0a812ee9424dfd090d1541d9a3f34f90bd109c969`.
- The recorded explored-state counters consistently sum to 319,968. They were
  not regenerated by a simulator.

`RESULT.json` contains the complete command output. The 35 new tests exercise
missing groups/cases/paths, duplicates, case and policy relabeling, modified
contracts, ambiguous JSON, altered verifiers, certificate and aggregate defects,
and reordered valid evidence. The existing 10 attribution and 12 transport tests
also passed. The test fixture contains 14 unchanged saved rows from two cases;
its subset aggregate expectations were prepared from retained group summaries,
not computed by the new validator. Adversarial mutants are created in memory or
temporary directories and do not alter accepted evidence.

## Exact scope and limits

- Completeness means equality to the retained finite case manifest, the four
  registered policies, and the checker-defined scheduler branches. It does not
  prove that the case manifest covers every plausible recovery scenario.
- Pinned expected artifacts authenticate membership and coverage comparisons.
  Semantic acceptance of `--rows` is not a claim of exact compressed-file byte
  identity. Use the unchanged payload manifest and reconstruction checks for
  exact archive identity.
- The original dynamics/coverage checker and prior attribution implementation
  are reused after byte verification. This is stronger composition and input
  validation, not a new independent dynamics implementation; shared
  specification errors remain possible.
- Group `states` and row `states_explored` are reconciled as recorded counters.
  Group `omniscient_feasible` values, witness files, predictions, resource usage,
  and historical chronology are not independently rederived by this command.
  The unavailable original chronology freeze and presentation-text hashes are
  not replaced or relabeled by public checksums.
- The library-level `audit_rows` function checks caller-supplied expectations.
  Only the CLI's pinned loaders provide the fixed published-expectation claim.
- No production reliability, empirical model efficacy, probability of incidents,
  policy superiority, general optimality, or repair of the six losses follows.

The original source, results, manifests and previous supplements are untouched.
This directory has its own provenance and tests; it is not retroactively inserted
into the historical scientific manifests.
